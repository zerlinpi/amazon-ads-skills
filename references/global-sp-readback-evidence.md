# Global Sponsored Products 207 receipt and readback evidence

This is a **read-only, single-item campaign-update** evidence contract. Use it in post-change review when an external, separately authorized Executor has already attempted a Global Sponsored Products campaign update. The helper `scripts/evaluate_global_sp_readback.py` never calls Amazon Ads, mutates accounts, retries requests, or reconciles Executor idempotency.

## Platform facts and scope

Amazon Ads' [Global Sponsored Products API guide](https://advertising.amazon.com/API/docs/en-us/guides/campaign-management/global-campaigns) documents HTTP **207** multi-status receipts for create/update/delete with per-request-index `success`, `error`, and `partialSuccess`. Query returns HTTP **200** with `nextToken` pagination. A global campaign may override `state` for individual marketplaces via `marketplaceConfigurations`; the top-level state is not every marketplace's configured state. Query `status.deliveryStatus` is delivery health, not the configured state. Some query status marketplace identifiers are marketplace IDs rather than ISO country codes.

Those facts are platform behavior, **not proof** that a particular connector can expose all required fields. A trusted external adapter must produce source-supported, identity-verified **effective configured state per marketplace**, resolving top-level state and any overrides using the actual query evidence. It must not guess from delivery status, infer unsupported marketplaces, or treat a missing override as evidence without the complete global query context.

## Supported marketplace identity (v1.44.0)

The [Amazon Global Sponsored Products API guide](https://advertising.amazon.com/API/docs/en-us/guides/campaign-management/global-campaigns), checked 2026-10-24, explicitly lists eligible country codes: `AE, AU, BE, BR, CA, DE, EG, ES, FR, GB, IN, IT, JP, MX, NL, PL, SA, SE, SG, TR, US`. The campaign, ad-group and positive-target readback helpers now share this dated eligibility list. The request must use an exact listed country code, including `GB` rather than `UK`. Malformed, unsupported, unverified or newly introduced codes return `Unknown`, even when an untrusted normalized request and readback echo the same token. This is a conservative local gate, **not** a claim that Amazon's list is immutable or that a raw marketplace ID is interchangeable with a country code. Reverify current official eligibility and adjust deterministic tests before adding future marketplaces. A valid country code does not independently prove account eligibility or query authenticity.

## Supported intent boundary (v1.33.0)

This evaluator can confirm only the requested campaign **configured effective states** and, when explicitly present, the supported **daily monetary marketplace budgets**. An external adapter MUST NOT interpret this `Confirmed` as verification of an ad-group default bid, target bid, placement adjustment, bid strategy, or other independent update. Any additional request key beginning `expected_` that is not `expected_effective_states` or `expected_marketplace_budgets` returns `Unknown` after valid 207 success, even when its value is an empty object. This is intentional forward-compatibility safety: new intended change dimensions require their own verified readback contract. HTTP 207 `error` / `partialSuccess` still takes precedence as `Partial`.

The official Global SP guide documents marketplace-local ad-group bids as a distinct entity/API resource; this campaign-only helper does not fetch ad groups or targets. Generic non-intent metadata remains compatible. Do not drop unsupported expected fields in the normalization layer to force `Confirmed`.

## Normalized input

Call `python -m scripts.evaluate_global_sp_readback < normalized-evidence.json`. This tool consumes one **single request item** only; batch receipts with additional indices return `Unknown` rather than a false batch-wide confirmation.

The normalized JSON envelope contains:

- `request`: nonempty `global_account_id`, `campaign_id`, unique `marketplaces` (one consistent country-code namespace), `expected_effective_states` keyed exactly by those marketplaces, and RFC3339 `completed_at`.
- `receipt`: integer `http_status: 207` and all three `success`, `error`, `partialSuccess` arrays, with exactly one unique `index: 0` across the arrays. Receipt status alone never proves readback.
- `readback`: matching global-account/campaign identity, source-system/acquisition-channel/connector identity, RFC3339 `observed_at` strictly later than request completion, `coverage_status: Complete`, `pagination_status: Complete`, `capability_status: Supported`, and `marketplace_states` with one source-observed `effective_state` for **every** requested marketplace. A trusted adapter must prove that normalized country codes map to the source's marketplace identifiers.

### Optional 207 campaign receipt identity (v1.38.1)

A 207 success index is necessary but not sufficient when the adapter retains explicit identities. If the normalized receipt provides `resource_type`, `global_account_id`, `campaign_id`, or `request_id`, each must bind to the intended campaign request. A receipt `request_id` cannot be accepted when the request lacks that identity. If the successful item includes a returned `campaign` object, it must contain a matching `campaignId` (native) or `campaign_id` (normalized); both aliases are checked if both exist. Supplied account identities and success-item correlation fields must also agree. Malformed or contradictory evidence is `Unknown`, not `Confirmed`. Index-only receipts remain compatible when the trusted adapter has no additional identity fields. This is a conservative repository guard, not a substitute for raw receipt preservation or independent adapter authentication.

`effective_state` is the source-supported configured `ENABLED`, `PAUSED`, or `ARCHIVED` state, not delivery status or performance. `Unknown`, missing, partial, unsupported, and unverified observations are not zero or paused.

### Optional raw marketplace identity crosswalk (v1.39.0)

The Global SP guide distinguishes country-code `marketplaces`/`marketplaceConfigurations` from raw marketplace IDs that can occur in query `status.marketplaceSettings`. A raw ID is **not** interchangeable with `US`, `GB` or another country code. An external adapter that retains any `marketplace_id` on a normalized `marketplace_states` row (or on a `marketplace_budgets` row when budget verification is requested) must also provide `readback.marketplace_identity_map`.

This repository-owned crosswalk is a list containing **exactly one entry for every requested country-code marketplace**. Each entry requires nonempty `marketplace` (country code), `marketplace_id` (raw source identifier), `evidence_status: "verified"`, and a `source` object with nonempty `source_system`, `acquisition_channel` and `connector_id`. Raw IDs and country codes must each be unique. Every state row, and every budget row when budgets are requested, must carry a `marketplace_id` matching the corresponding crosswalk entry. Missing, partial, duplicated, malformed, unsupported or contradictory evidence yields `Unknown`, not `Confirmed`. The crosswalk source may differ from the campaign query source when explicitly identified.

A crosswalk is **an assertion by the trusted external adapter**, not cryptographic verification of the original API response or an official Amazon-mandated schema. The caller must retain raw query, mapping source and pagination evidence externally. In particular, successfully mapping a raw ID from `status.marketplaceSettings` **does not** make `deliveryStatus` a valid configured `effective_state`. Effective configured state must still be independently derived from the complete campaign state and overrides. When no raw marketplace IDs or crosswalk are provided, the existing trusted country-code-only envelope remains compatible; absence of raw metadata is not independent proof of mapping correctness.

### Concrete Global SP identity provenance (v1.65.0)

An explicit `request.global_account_id`, `campaign_id` or optional `request_id` must be a concrete, unpadded identity. A readback's `source_system`, `acquisition_channel` and `connector_id` must also be concrete. When an optional raw marketplace crosswalk is supplied, every `marketplace_id` and its independent `source` identities must be concrete before a matching echoed row can count as verified. Whole-label `Unknown`, `Unsupported`, `Partial`, `Missing`, `Unavailable`, `Not Available` and `Not Supported` (including hyphen/underscore/space variants) are not identities; repeated placeholders return `Unknown`, never `Confirmed`. Valid synthetic IDs containing `unknown` as a substring remain accepted. Existing index-only receipts and country-code-only readbacks are compatible; source authenticity, advertiser/campaign eligibility and marketplace delivery remain external evidence requirements.

This is a repository-owned read-only provenance guard. It is **not** an Amazon Ads native ID format, authentication of external adapters, a general campaign eligibility assertion or an authorized Executor. A successful 207 receipt alone still cannot prove an applied state.

### Optional configured-state row lineage (v1.32.0)

A trusted adapter may supply row-level `source`, `observed_at`, `global_account_id`, or `campaign_id` on `marketplace_states` rows. When supplied, the values must not contradict the trusted readback envelope or the request. Row source must match `source_system`, `acquisition_channel`, and `connector_id`; row observation time must be strictly later than the update completion and no later than the envelope observation; row account/campaign identity must match the request. Incomplete explicit source, invalid timestamps, and contradictions return `Unknown` rather than `Confirmed`. Do not silently discard conflicting row metadata during normalization.

These row fields are optional **repository-owned conservative evidence**, not Amazon API-required fields. A trusted single-envelope adapter can omit them, but omission is not independent proof of per-row lineage. Valid HTTP 207 `error`/`partialSuccess` still returns `Partial` before readback checks.


## Optional marketplace monetary-budget readback (v1.30.0)

The state-only single-item contract remains valid when no budget change is being evaluated. When the external Executor's intended change includes a **marketplace monetary budget**, the normalized `request` MUST additionally contain `expected_marketplace_budgets` keyed exactly by `request.marketplaces`. Each value must carry `currency_code` (three uppercase letters), a **plain nonnegative decimal string** `amount` (for example, `"100.00"`), `budget_type: "MONETARY"`, and `recurrence: "DAILY"`. The current optional comparison deliberately supports only daily monetary budgets; other types/periods remain `Unknown` rather than being interpreted as zero or a supported update.

The normalized `readback` must separately provide `budget_coverage_status: "Complete"`, `budget_pagination_status: "Complete"`, `budget_capability_status: "Supported"`, and exactly one `marketplace_budgets` row per requested marketplace. Each row carries `marketplace`, `currency_code`, `amount`, `budget_type`, `recurrence`, and `evidence_status: "observed"`. The adapter must preserve native source precision when converting an API numeric budget to a decimal string, and prove the source marketplace/currency mapping. Generic state-readback capability does **not** prove budget observability.

When a trusted adapter supplies **row-level** `source`, `observed_at`, `global_account_id`, or `campaign_id` on an individual `marketplace_budgets` row, those assertions must not contradict the enclosing readback and request. Explicit row source identity must match `source_system`, `acquisition_channel`, and `connector_id`; row observation time must be strictly after request completion and no later than the enclosing `readback.observed_at`; row account/campaign identity must match the request. Contradictions, incomplete row source objects, or malformed timestamps are `Unknown` rather than budget `Confirmed`. Row-level fields remain optional for adapters whose **single trusted readback envelope** already covers all its rows; absence of optional row metadata is not independent proof of per-row freshness or provenance. Do not silently drop contradictory source metadata during normalization.

Budget evidence is compared by marketplace **without FX conversion**. `"100"` and `"100.00"` compare numerically equal only with the same verified currency, type and recurrence. Currency mismatch, amount mismatch or recurrence mismatch is `Drifted`; missing market, partial/truncated/unsupported budget evidence, nonfinite/negative/malformed values, unobserved row or incomplete source identity is `Unknown`. Explicitly observed `"0"` is distinguishable from missing evidence; this evaluator does not assert that any given zero budget is permitted by Amazon or authorize a write. Any receipt `error`/`partialSuccess` still yields `Partial` before readback interpretation.

This is **not** a general bid readback, multi-item batch reconciler, exchange-rate engine, budget-policy calculator, or proof of actual delivery/spend. Other Global SP budget variants, ad-group bids, target bids, auto-expansion and execution/idempotency remain outside this narrow contract. A caller must not claim budget application `Confirmed` by omitting the optional budget expectation when a budget was part of the intended change.

## Conservative classifications

- `Confirmed`: only an unambiguous single-item 207 success plus complete, newer, same-identity query readback with every marketplace configured as intended. **Not** proof of campaign delivery, performance, or causal lift.
- `Partial`: a valid 207 receipt contains an `error` or `partialSuccess`; no batch-wide success inference, even if a later snapshot appears to match.
- `Drifted`: the successful receipt has complete, source-supported readback but one or more marketplace effective configured states differ.
- `Unknown`: malformed/ambiguous receipt, unsupported status, missing or incomplete query, stale evidence, source or account identity mismatch, duplicate/missing marketplace, or invalid configured state.

This helper is not a generic Global SP request/response validator, not a multi-item reconciliation engine, and not a replacement for the versioned material-control comparator. Preserve the raw receipt and query evidence externally. The normalized envelope is an input assertion by the trusted connector/adapter, not cryptographic verification of that adapter.

## Optional native campaign configuration cross-check (v1.40.0)

If the trusted external adapter retains the **complete native campaign query resource** as `readback.raw_campaign`, the read-only evaluator independently recomputes per-marketplace configured state from that resource. The object must contain native `campaignId`, `adProduct: "SPONSORED_PRODUCTS"`, `marketplaceScope: "GLOBAL"`, exact unique `marketplaces`, valid global `state`, and a complete `marketplaceConfigurations` list (use `[]` when there are no overrides). Each configuration needs a unique in-scope `marketplace` and an `overrides` object; `overrides.state`, when present, must be a supported configured state. Otherwise the global `state` is inherited. If a supplied native resource contradicts the normalized per-marketplace `effective_state`, account/campaign identity, or scope, return `Unknown` instead of `Confirmed`. A complete native resource that agrees with the normalized readback but differs from the intended request remains `Drifted`.

**Important:** `status.deliveryStatus` and `status.marketplaceSettings[].deliveryStatus` are delivery-health observations, never substitutes for configured state. A native `status` object is ignored for this configured-state derivation. The optional `raw_campaign` is retained under the same trusted query/readback envelope, not an independently authenticated API payload or proof that the adapter faithfully collected all pages. Country-code-only legacy envelopes remain compatible; omission of optional raw evidence is not proof of raw-field lineage. No Amazon Ads writes, retries, idempotency or executor reconciliation are performed.


## Optional query pagination trace (v1.41.0)

A trusted external adapter may preserve the **campaign query** page chain as `readback.pagination_trace` alongside its existing `pagination_status: "Complete"`. When present, the trace is mandatory-to-validate, not optional-to-ignore. The repository-owned shape is:

- `query`: `global_account_id`, `campaign_id`, `ad_product: "SPONSORED_PRODUCTS"`, `marketplace_scope: "GLOBAL"`, and a nonempty stable `query_fingerprint` for the exact query filters. The fingerprint is an external assertion, not a hash verified against native HTTP requests.
- Optional `query.source`: when supplied, the query-level source must match the complete readback/page source. An omitted query source is compatible; explicit null, incomplete, malformed or conflicting source yields `Unknown` (v1.44.1). This is an adapter-internal consistency check, not HTTP authentication.
- `pages`: a nonempty ordered list of page records. Each has `request_token` (null for the first page), `next_token` (null only on the terminal page), `observed_at` (RFC3339 after write completion and no later than the readback envelope), matching `global_account_id`, `campaign_id`, `query_fingerprint`, and a complete `source` matching the readback envelope.

Every non-null `next_token` must be a nonempty string and equal the following page's `request_token`; continuation tokens must not repeat. Page observation instants must be nondecreasing. A missing terminal page, token gap/cycle, mixed filter/account/campaign/source, malformed page, or stale/out-of-order observation is `Unknown`, never an implied empty page or zero. A single-page query uses both tokens null.

This is an **internal consistency check of a trusted adapter's retained evidence**, not proof that every resource was returned, that query filters were authentic, or that an external API response was not tampered with. The existing `coverage_status`, `pagination_status`, `capability_status`, marketplace rows and source checks remain mandatory. This optional campaign query trace does **not** prove separately required marketplace-budget query pagination; budget completeness remains an independent requirement. Absence of optional trace preserves compatibility but is not positive proof of a native page chain. No API mutation or Executor reconciliation is performed.

## Native campaign-to-query-page provenance binding (v1.42.0)

When a trusted adapter supplies **both** `readback.raw_campaign` and `readback.pagination_trace`, it must also supply `readback.raw_campaign_provenance` to bind the retained native campaign resource to one specific page of the same source-filtered query. This repository-owned object contains `global_account_id`, `campaign_id`, `query_fingerprint`, integer zero-based `page_index`, `observed_at` (RFC3339), and the full `source` object. Its source and timestamp must equal the selected page's source and observation instant, and its account, campaign and fingerprint must match the query. Missing, malformed, contradictory or unbound provenance returns `Unknown`. A JSON boolean is not a valid page index.

Native-only and pagination-only legacy envelopes remain supported. Explicit provenance without both surfaces is `Unknown`; the adapter must not assert a verified page binding it cannot show. A complete bound readback that differs from intended state remains `Drifted`. This is **not** independent authentication of the HTTP response, proof of complete resource coverage, or an Amazon-mandated schema. The authorized external Adapter/Executor remains responsible for source integrity, raw query retention, writes, retries and reconciliation.

## Optional native campaign monetary-budget cross-check (v1.43.0)

The official Global SP campaign query resource can include `budgets[]` within the **campaign resource itself**. This feature does **not** assume a separate native budget-query endpoint or use campaign configured-state pagination as independent proof of a different query. When the request includes `expected_marketplace_budgets` and the trusted adapter explicitly retains `readback.raw_campaign.budgets`, the read-only evaluator checks that the retained native budget configuration agrees with the independently normalized `marketplace_budgets` rows. This check runs only after the existing campaign identity/state, pagination, source, time, and normalized budget coverage checks.

The supported retained native shape is exactly one `budgets[]` entry with `budgetType: MONETARY`, `recurrenceTimePeriod: DAILY`, and `budgetValue.monetaryBudgetValue.marketplaceSettings[]` covering each requested marketplace exactly once. Each setting has `marketplace` and `monetaryBudget: {currencyCode, value}`. The trusted adapter MUST preserve the native `value` JSON numeric lexeme as a plain nonnegative **decimal string** before handing the normalized evidence to this helper. Python JSON floats, booleans, inferred missing amounts and FX conversions cannot prove exact source precision. Exact Decimal comparison permits different textual precision (`100.00` versus `100`). Malformed, unsupported, duplicate, missing, out-of-scope, or contradictory native budget evidence returns `Unknown` instead of `Confirmed`. A native and normalized budget that agree with each other but differ from the requested budget still returns `Drifted`.

Legacy envelopes without native `budgets` remain compatible, including native-state-only resources; omission is **not proof** that native budgets were verified. State-only requests do not claim monetary-budget verification. When `raw_campaign` and `pagination_trace` are both supplied, the existing `raw_campaign_provenance` binds the **entire retained campaign resource**, including budgets, to the query page. This is an adapter-internal consistency check, not independent HTTP authentication, completeness certification, live Ads execution, or a guarantee that budget rules and other effective controls were unchanged.

## Optional native query request filter binding (v1.45.0)

The official [Global SP campaign query guide](https://advertising.amazon.com/API/docs/en-us/guides/campaign-management/global-campaigns), checked 2026-10-24, documents a POST campaign query using `adProductFilter`, `marketplaceScopeFilter`, `campaignIdFilter`, optional `maxResults`, and `nextToken`. A trusted adapter can optionally retain `readback.pagination_trace.query.request_filters` plus each page's `request_body`. This is a repository-owned evidence representation, **not** an Amazon-mandated schema or independent raw HTTP authentication.

When present, `request_filters` must contain exactly `adProductFilter: {include: ["SPONSORED_PRODUCTS"]}`, `marketplaceScopeFilter: {include: ["GLOBAL"]}`, and `campaignIdFilter: {include: [request.campaign_id]}`; it may also contain a positive integer `maxResults`. No additional filters or continuation token belong in this declared base filter set. Every page must supply a `request_body` with precisely the same filters; its `nextToken` must be absent or null for the first page, and must equal the pagination trace's request token for every subsequent page. Malformed/partial bodies, mismatched campaign filters, different page sizes, extra state/name filters, or inconsistent continuation requests return `Unknown`, not `Confirmed`.

Legacy traces with neither declared native filters nor page request bodies remain compatible; an orphan page request body without a declared filter set is `Unknown`. This does not recompute or cryptographically authenticate `query_fingerprint`, prove that the adapter preserved unmodified native HTTP payloads, or guarantee that Amazon returned every matching resource. External authorized Adapters/Executors retain responsibility for raw response integrity, credential safety, query collection, pagination coverage, and live write/reconciliation. No Ads API calls are made by this helper.


## Optional native campaign response-page membership (v1.46.0)

Amazon's [Global Sponsored Products API guide](https://advertising.amazon.com/API/docs/en-us/guides/campaign-management/global-campaigns), checked 2026-10-24, shows a campaign query returning a `campaigns[]` array and `nextToken`. A trusted external adapter may optionally retain the native query response for each page as `readback.pagination_trace.pages[].response_body` with those two exact keys. This is a repository-owned evidence contract, not an Amazon-mandated adapter format or independent HTTP authentication.

When **any** page supplies `response_body`, **all** pages must supply a response object containing an explicit `campaigns` array and `nextToken` value matching that page's declared `next_token`. The complete `readback.raw_campaign` and `raw_campaign_provenance` must be present. The intended campaign must appear exactly once across all page arrays, as a full object equal to the retained native campaign, and its page index must equal the declared provenance index. A wrong/extra campaign, duplicate campaign, missing member, wrong page, mismatched native configuration, malformed response or missing page response is `Unknown` rather than `Confirmed`. Empty arrays on other pages are valid evidence of zero matching campaigns **only within the supplied page response**, not proof of global data completeness.

Legacy pagination traces with **no** retained `response_body` remain compatible; absence of raw page responses is not positive evidence of resource membership. This comparison cannot prove the adapter retained unmodified HTTP bytes, that no API results were omitted, or that a campaign update improved performance. Preserve exact native numeric lexemes and source identity in trusted adapter capture. All live writes, retries, reconciliation and API credential handling remain external.
