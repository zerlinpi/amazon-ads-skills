# Amazon Ads 优化框架

所有优化 Skill 使用同一推理顺序，避免只看单一 ACOS 做机械动作。

## 1. 明确目标

优先读取用户/账户目标：
- Target ACOS / Target ROAS
- 盈亏平衡 ACOS
- 销售增长
- 利润增长
- 新品冷启动
- 排名/类目占位
- 清库存
- NTB/品牌获客

若目标缺失，默认只做诊断和保守建议，不自行设定利润目标。

## 2. 校验数据

检查：
- 日期范围与比较基线；
- Marketplace/币种/时区；
- 归因窗口；
- 广告类型；
- 数据是否完整；
- 促销、价格、库存、Buy Box 等外生因素。

数据不完整时降低 `confidence`，必要时停止动作建议。

## 3. 判断样本量

不要使用固定“点击 X 次就必须调整”的绝对规则。优先使用：
- 历史 CVR；
- 当前 CPC；
- 商品价格；
- 目标 CPA/ACOS；
- 实际点击/订单；
- 时间跨度。

可将 `expected_clicks_per_order = 1 / historical_cvr` 作为参考，并要求多个期望转化窗口后再对 0 订单实体做高置信度判断。

若没有历史 CVR，可使用同层级父级或相似 ASIN 基线，并明确标记为代理基线。

## 4. 建立基线

优先顺序：
1. 同实体历史同期；
2. 过去 4-8 周滚动基线；
3. 同 campaign/ad group；
4. 相似 ASIN/关键词群；
5. 账户整体。

不得把不同旺季/大促与普通周直接比较而不做说明。

## 5. 诊断原因

先诊断，再动作。常见原因：
- CPC 上升；
- CVR 下滑；
- 流量结构改变；
- 搜索词偏移；
- 预算受限；
- 版位 mix 改变；
- 商品价格/促销改变；
- 库存或 Buy Box 问题；
- 新词探索期；
- 归因延迟。

## 6. 生成动作候选

每个动作必须包含：
- `action_type`
- `entity_type`
- `entity_id`（若已知）
- `current_value`（如适用）
- `proposed_value`（如适用）
- `reason`
- `evidence`
- `confidence`
- `mode`
- `guardrails`
- `validation_window`
- `rollback_condition`

## 7. 冲突消解

同一实体同一参数只保留一个最终动作。发生冲突时：
1. 保护账户/止损动作优先；
2. 数据质量问题优先于优化；
3. 高置信度优先于低置信度；
4. 利润目标优先遵从用户明确目标；
5. 无法判定时只输出人工复核项。

## 8. 验证窗口

执行建议后需要等待足够数据再二次调整。窗口取决于：
- 流量速度；
- 点击/订单样本；
- 归因延迟；
- 大促状态。

不得对刚调整不久的实体连续追涨杀跌。

## 9. 输出层级

推荐顺序：
1. 结论摘要；
2. 关键异常/机会；
3. 证据；
4. 建议动作；
5. 风险与假设；
6. 需要补充的数据；
7. 验证窗口与回滚条件。
